## Product defects (for the repair pass)

Screenshots are in this worktree under `.artifacts/s3-e2e-2/defects/`.

### D1: staff Album (`/staff/tasks`) crashes for every staff member

- **Specs:** coverage-manager (review journeys), coverage-acceptance AC-29, amenities ×6, amenities-mobile, knowledge-b03-cd ×2, knowledge-b03-ef, contrast-dark (staff).
- **Steps:** sign in as any staff member, which lands on `/staff/tasks`.
- **Expected:** Album Home with the "Asked for" section.
- **Actual:** "We couldn't load Home / Try again". The server logs `Attempted to call askedForItems() from the server but askedForItems is on the client`.
- **Cause:** `app/staff/tasks/page.tsx:188` (a server page) calls `askedForItems` from `components/nabalens/requests/staff-requests.tsx`, which starts with `"use client"`. It comes from S2-REQ.
- **Screenshot:** `D1-staff-home-crash.png`.
- **Note:** S3-E2E-1's staff journeys will hit this too.

### D2: Ask for another photo dialog overflows at 320 px

- **Spec:** `ac15-19-review.spec.ts`, "AC15-AC19 layout".
- **Steps:** as a manager at 320 × 640, open `/manager/review/photo/<id>` and press Ask for another photo.
- **Expected:** no sideways scroll.
- **Actual:** the dialog is 24 px wider than the screen. The chip "People or personal details in shot" runs off the edge.
- **Screenshot:** `D2-D3-review-detail-320.png`.

### D3: manager tab labels break mid-word at 320 px

- **Spec:** the same test (a soft assertion).
- **Steps:** as a manager at 320 px, look at the bottom bar.
- **Expected:** each label reads on one line.
- **Actual:** "Overview", "Review" and "Requests" wrap inside the word ("Overvie / w", "Reques / ts").
- **Screenshot:** `D2-D3-review-detail-320.png`.

### D4: a catalogue question without a knowledge rule never gets a photo slot

- **Spec:** `ac24-25-facts.spec.ts`, "FA-32 (AC24 context)".
- **Steps:**
  1. Add `pool_table` at a venue.
  2. Staff answer Yes and attach a photo.
  3. Read `private.coverage_slot_rows(venue)`.
- **Expected (FA-32):** a Yes needs a reviewed photo where the catalogue asks for one. `pool_table`'s evidence rule is `photo`, so a counted Facilities slot should exist.
- **Actual:** there is no row.
- **Cause:** `coverage_slot_rows` only includes checks where `private.knowledge_in_scope` is true, which means checks on `knowledge_working_list`. `knowledge_set_working_list` refuses any key with no `knowledge_question_rules` row (`knowledge_rule_missing`). Only 16 of the 48 catalogue questions have rules, so the other 32, including pool table and darts, never count in coverage, metrics or the Overview.
- **Side effect:** AC24's own result holds only because no slot exists at all.
- **Screenshot:** `D4-pool-table-yes.png` (the failure is in the database read).

## Smaller findings

- **F5. Percent rounding differs between screens (from reading the code; not asserted).** The admin Overview floors to a whole number (`ofWords` in `lib/admin/overview.ts`, `Math.floor`, so 1 of 3 shows "33%"). Metrics and the manager Overview use one decimal (`coverageWords` in `lib/knowledge/facts.ts`, "33.3%"). The n of N values match (AC39 passes). Pick one rule per concept.
- **F6. A reconfirmation's feedback is lost.** On `/manager/venue/facts`, "Still right: <place>" removes the row, and the "Confirmed as still right." status goes with it. The page only reads "No space photos are due a check.", so nothing is announced to a screen reader. AC30 still passes.
- **F7. A broken thumbnail in My uploads has no fallback.** When a thumbnail fails, Me › Your photos (S2-STAFF) shows the browser's broken-image icon, with no retry or notice. The portfolio gallery below it re-signs once and then shows "1 preview could not load. Try again". Screenshot: `F7-my-uploads-broken-thumbnail.png`.
- **K4 still applies.** "Label corrected" reaches the staff Notices (AC15 passes on that). I did not test staff Me's chip, because `my_uploads` cannot see review label fixes (code read only).
- **Fixture gap, not a product defect.** The amenities e2e world never puts checks on the working list. The admin venue template does that in the product (`venue_apply_template`). My AC25 spec adds it in the admin's own session.

## Assumptions

- **AC37:** only the review flows (S3-E2E-1 owns staff upload and labelling). Pressing keys after `focus()` counts as keyboard operation. One test also proves the button is reachable with Tab.
- **Fixtures and decisions:**
  - A starting state that is not the criterion under test (an accepted photo, a menu draft, a garden accepted 100 days ago) is fixture setup. It is written in the person's own session where an RPC exists, or by the service role or psql where the product has no other way (time travel).
  - Every decision a criterion is about is made on the page.
- **AC22, AC20, AC33:** deferred by FA-41, FA-42 and FA-40. Each has a spec that pins today's documented behaviour.
- **Next.js build notice:** the first `next build` stopped with a "known security vulnerability … upgrade Next.js" notice, and a retry built normally. Following the brief, I did not upgrade dependencies. The coordinator or owner should look at this.
