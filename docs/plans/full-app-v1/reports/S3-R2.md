### V12: reviewed area label

`set_media_area_label` (only definition: 20261116170000). Once the live label

### D4: knowledge rules for every catalogue question

Confirmed. The local catalogue has 39 questions, and 32 of them had no rule.
The report's "48" counts something else, but its "32 without a rule" matches.
`20261118121200_knowledge_rules_all_questions.sql` gives each of the 32 rule
version 1, using the `docs/knowledge/access-and-rights.md` §6 plan default:

- **Accessibility category** (`accessible_parking`, `accessible_seating`,
  `accessible_toilet`, `braille_menu`, `hearing_loop`): sensitive
  accessibility claims, like `step_free_entrance`. The rule is
  `venue_manager`, self-confirmation allowed and recorded, no automatic
  completion.

  `guest_toilets`. The rule is `none`, with automatic completion.

(`change_kind 'rule'`), following the 104000 pattern, and both definition-change
notes. I chose to add rules rather than let the working list accept a
question with no rule, because the resolver and the confirmation logic read
`private.knowledge_rule()` throughout.

### F5: percent rule

**Helper for S3-R6: `percentWords(n: number, d: number): string | null`,
exported from `lib/knowledge/facts.ts`.**

The rule is one decimal place, with a trailing `.0` dropped ("50%",
"83.3%"). It never shows 100% while something is missing (1999 of 2000 is
"99.9%") and never 0% once something counts (1 of 2000 is "0.1%"). It
returns null when `d <= 0` or a value is not finite. `coverageWords` uses it,
so the manager Overview, Venue and metrics (`lib/metrics/model.ts` `ofWords =
coverageWords`) follow it already.

To switch the admin Overview, S3-R6 changes `lib/admin/overview.ts`
`ofWords` to `pct: percentWords(n, d) ?? ""`. Test:
`tests/unit/knowledge-facts.test.ts`.

## Decisions for the coordinator to record

1. **V12:** a reviewed area label cannot be changed or cleared by its
   uploader. Reviewed means a latest decision of accepted,
   needs_another_photo or not_used. A withdrawn label can still be cleared.
   Error `area_photo_decided`.
2. **D4:** every catalogue question has a knowledge rule, using the
   access-and-rights §6 default: Accessibility needs venue manager
   confirmation (self allowed); every other question needs none and
   auto-completes. A question added to the catalogue later needs its rule in
   the same migration.
3. **F5:** one percentage rule for "n of N", `percentWords`.
4. **Open question, not changed:** a check a manager adds through
   `amenity_add_checks` does not join the working list on its own, so it has
   no coverage slot until an admin adds it, through the venue template or
   `knowledge_set_working_list`. Joining it automatically would move the
   check onto the knowledge write path, where the legacy
   `amenity_submit_finding` raises `knowledge_path_required`. That needs a
   product decision, so I left it as it was.
