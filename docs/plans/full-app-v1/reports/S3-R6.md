## Performance: metrics_overview

I profiled a seeded stack (27 active venues) with `pg_stat_user_functions` (`track_functions = 'all'`) and EXPLAIN ANALYZE. Two problems, both fixed by forward migrations:

1. **`private.media_duplicate_suppressed` scanned every photo in the database on each call.** It put `asset_is_accepted(o.id)` in the join's WHERE. A security definer function is never inlined, so the planner filtered the whole `media_assets` table with it before joining to the one original. EXPLAIN showed `Seq Scan on media_assets o, Filter: deleted_at IS NULL AND asset_is_accepted(id)`, even when the photo isn't a duplicate. That was 46,170 `asset_is_accepted` calls and 730 of about 2,000 ms. The cost grew with every photo in the database, which is why it showed up late in the security suite. Fixed in 20261118125300: the function now finds the original by primary key, then asks about that one photo.
2. **`metrics_overview` ran `metrics_venue_json` three times per venue** (81 calls for 27 venues). The lateral subquery was flattened, so the call was repeated in the aggregate and in both ORDER BY keys. Fixed in 20261118125400 with a materialized CTE.

Result: one `metrics_overview` read went from **995 ms to about 220 ms** on the same stack. I compared the old and new bodies in one transaction: **identical output** (`old = new` returned `t`). The indexes on every table the metrics filter by venue and time were already there; none were missing.

## Decisions made (for the coordinator to record)

1. **A venue-corrected photo is never restored at its declared venue (V19).** Corrections are append-only and always name another venue, and moving a photo into another venue's review isn't built. So the photo stays withdrawn, and the way to use it at the right venue is a new upload there. The alternative, re-deciding the declared venue's approvals, would bring back a wrong-venue photo.
2. **A switched-off venue is archived (V22).** In both the backfill and the app reading, `active = false` means archived, whatever `operating_status` says. Choosing Open or Temporarily closed for it is a deliberate reopening, recorded as `venue_restored`.
3. **Checks due count each subject once (V20).** A facility check counts once as a fact when its fact is due. A recheck on a facility also makes its fact due, so in practice facilities appear as facts. The total links to its biggest part, and each part links to its own page.
4. **The review-age alert uses the admin's backlog setting with the monitoring comparison** (more than N days), so the Overview and monitoring always agree (V21).
5. **Admin landing is `/admin/overview` (K7).** `/admin` stays the Library and the area prefix. The area not-found page's "Go to Content" still links to `/admin`.
6. **Suspend (K11) is an admin Library action that withdraws approvals through the review functions.** It is not a new state that coverage reads, so coverage rules and other workers' functions are untouched, and the review history shows who suspended and why. Restore never brings approvals back. Managers' own Suspend (spec §7 M3) and destination update work (M3 "no longer represents") are still open.
7. **Percentages use one decimal for now (F5)**, through `coverageWords`, until S3-R2 picks the rule.
