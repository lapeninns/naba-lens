## 2. scan-bundle: `createRequest` (2 chunks), `savePreferences` (3)

No client component imports a server module, and no shared module re-exports a server name. Both hits were fingerprint collisions. The scanner treats every exported name of `lib/server/**` (10+ characters) as a server-only fingerprint:

- `createRequest` in `.next/static/chunks/030zdrbfh_z0-.js` is tus-js-client's own `httpStack.createRequest` (the upload library), which shared its name with `lib/server/requests#createRequest`.
- `savePreferences` in three chunks is the `actions.savePreferences` prop of `components/nabalens/me/notices-inbox.tsx`, which receives the Server Function `saveNotificationPreferencesAction`. It shared its name with `lib/server/notifications#savePreferences`.

Change: the two server-only functions are renamed `createManagerRequest` and `saveNotificationPreferences` (callers, and the unit tests that mock them, updated). The scanner rule is unchanged. `S1-OPS.md` notes the rename.

## 4. exec / privacy-runtime

CI's three lanes failed only because a stale `next start` held 3457 (`…/login is already used`; `privacy-runtime: port 3457 is already in use`). On my stack (port 3623):

- **Playwright chromium** (`scripts/ci/playwright.config.ts`, the run-suites exec step): the web server's `next build` stopped once on the Next.js security notice; the retry ran **353 passed, 29 skipped, 0 failed (44.3 min)**.
- **privacy-runtime** then failed 3 of 12. The port clash had hidden these failures:
  - Its admin signs in over HTTP but never passed the second step: test out of date (FA-23). It now raises the admin to aal2 with `@supabase/ssr`'s own cookie handling on the role's jar; the new tokens join the secrets the server log must not contain.
  - Staff B's thumb and preview of staff A's unreviewed photo are 404, not a redirect: test out of date (FA-20). It now asserts a private 404 with no `location`. The accepted redirect is covered in gaps-http.
  - **Product defect, fixed (`ea0225fe0`).** The same suite's `beforeAll` invited a staff member as that aal1 admin, and it worked. `lib/server/accounts` decided who was calling with `toAuthState` alone, which never reads the session's assurance level, then acted with the service role, where the database's aal2 check does not apply. An admin signed in by email link only could invite and re-invite staff, deactivate and edit accounts (and `memberships`/`avatar` used the same check). `resolveCaller` now applies `getAuthState`'s FA-23 rule (`mfaRequirement` on the verified JWT's aal; factors read for admins and managers at aal1; unreadable fails closed). Regression: `auth-invites` "an admin who has not passed the second step": invite, resend, deactivate and edit are refused, no user, email or profile change, and after `passMfa` the same browser may invite. It fails on the old code (the invite came back `sent`) and passes on the new.
- After the fix, privacy-runtime: **12 passed, 0 failed, 0 skipped: PASS**. Focused Playwright on the journeys using the changed account code (staff-accounts, manager-workspace, slice, auth-guards, auth-return, negative, profile-outage, ac40-manager-invite): **55 passed**.

## Decisions

- **Account checks follow getAuthState (FA-23).** A manager who turned MFA on and is still at aal1 is also refused by the account functions (profile photo, memberships), as every page already refuses them. Same rule everywhere.
- **Fixture venues are retired, not deleted,** before each security file. Integration and Playwright are unchanged; they create their own venues.
- **Server-only names were renamed rather than the scanner relaxed,** so the fingerprint rule keeps its strength.
- **Recorded, not changed:** `amenity_check_set_applicability` reports `not_permitted` (not `not_found`) to another venue's manager, which shows that a check id exists. Ids are random UUIDs; changing it needs a migration. The notification job's admins × exceptions cost is fine at production size.
- The Next.js build printed a security-vulnerability notice recommending an upgrade. Not upgraded, as briefed; this is for the owner.
