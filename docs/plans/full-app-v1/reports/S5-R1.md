## Decisions (recommended options taken)

1. **One rule, read once.** `private.menu_optional_item_ids` returns the dish slots that `coverage_slot_rows` marks `inactive`. The dish `inactive` state is produced only by FA-51. Each reader joins it, and none re-derives the rule from `menu_item_packaging`.
2. **Optional items stay listed.** FA-51 says they are listed and take photos, so the full lists keep them. Only gap filters, status filters and counts leave them out.
3. **Headline `optional` on manager reads** (rather than a new column) for an uncovered optional item with nothing waiting. A covered or waiting optional item keeps "Has a photo" / "Awaiting review" because those are true. **Staff read** gets a boolean `optional` column, because it has no headline column.
4. **Status filters exclude optional items entirely.** That includes `covered` for an accepted optional photo, so every filtered list equals the Overview count beside it.
5. **Photos waiting on an optional item still count as photos to review** (Overview `pending_photos`, Our menu `pending_candidates`), because they still need a decision. They do not count as items awaiting review.
6. **Word.** The chip uses Album's FA-51 word **Optional** (`OPTIONAL_SLOT_WORD`) in a `closed` tone, so no new state word is added.
