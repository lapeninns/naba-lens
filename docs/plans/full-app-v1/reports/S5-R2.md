# S5-R2: Review shows the FA-52 brief (Y4)

Repair of finding **Y4** in `reviews/S5-review.md` (should-fix): the manager
review screen (Review in a thumb) ignored the FA-52 brief order. Branch
`fa/s5-r2`, based on `96be105d0`.

## What was built

- **One brief resolver on Review.** `reviewContext` in
  `app/manager/review/_shared/album-review.tsx` now reads
  `public.slot_briefs` for the manager's venue with open requests
  (`loadSlotBriefs(actor, { venueId, includeRequests: true })`), the same
  resolver `loadAlbum` uses for Album tiles, the slot page, Match and Asked
  for. The stage looks up each photo's brief by Album's slot key:
  `dish:<item id>` and `area:<subject id>`. So the reviewer sees the open
  request's brief, else the manager's album brief, else the catalogue brief,
  else the category's shot template, the words staff were given (DESIGN.md
  §2 principle 4, §5 Brief). A template change now reaches Review.
- **Fallback only on failure.** `getAlbumBriefs` (album_briefs: the dish's
  own, else its section's) is read only when the `slot_briefs` read fails or
  throws, so Review still shows the manager's brief in that case. It is not
  read at all when the resolver answers.
- **Area photos get a brief.** `AreaPhotoCard` carries `subjectId`
  (`area_photo_queue` already returned `subject_id`; no SQL change).
  `fromAreaCard(card, context)` takes the resolved `area:<subjectId>` brief.
  Before, it was hard-coded to null.
- **Model.** `ReviewContext.slotBrief` (slot key to resolved text) comes
  first in `fromMenuCard`; `itemBrief`/`sectionBrief` are documented as
  fallback only. `ThumbReview` passes the context to `fromAreaCard` on the
  first render and on area re-reads.
- **Elsewhere.** I checked every place a slot brief is shown: Album tiles,
  the slot page, Match and Asked for already use `loadAlbum`, so
  `slot_briefs`. New request › From a slot uses `slot_briefs` with
  `include_requests = false` (by design). The manager's Album places and
  briefs editor (`/manager/album`) edits album_briefs and is correctly not
  resolved. Review was the only reader showing a brief from another source.

## Decisions

1. Use the resolver's read whenever it succeeds and skip album_briefs then
   (the review's proposed fix). The fallback runs after the resolver fails,
   one round trip later, only in that case.
2. Review shows the brief text only, not the example photo. Y4 is about the
   words the reviewer judges against. Adding the example to the stage would be
   a UI change outside this finding, so it is left for a later batch if wanted.
3. With `include_requests = true` the manager reads the open request chosen
   by the resolver's order (the caller's own assignment first, then priority,
   date and age). A manager is rarely the assignee, so for one open request it
   is the same brief staff see. The security test checks they match.
