# Full App v1: sprint plan

Spec: [NabaLens-Full-App-Specification-v1.0.md](../../spec/NabaLens-Full-App-Specification-v1.0.md). Decisions: [decisions.md](decisions.md). Requirement checklist: [checklist.md](checklist.md) (every requirement with its sprint, owner and acceptance check). Progress log: [progress.md](progress.md).

Delivery branch `feat/full-app-v1`; one bundled PR. Workers run on T3 Code (accounts `claude-team-01` to `08`), each in its own worktree branched from the delivery branch at the start of its sprint. The coordinator merges, resolves conflicts, runs full checks, and keeps this plan and the checklist current.

## Rules for every task

1. Read `AGENTS.md`, `docs/design-system/DESIGN.md`, the spec sections named in the task, and [decisions.md](decisions.md). Decisions FA-1 to FA-44 are binding; do not reopen them.
2. Stay in the files your task owns. Touch another task's file only minimally, and list it in your report.
3. Migrations use only your task's timestamp range, are additive, and follow the pattern of `supabase/migrations/20261117120000_album_places.sql`: RLS on, no direct table grants, `security definer` functions with `set search_path = ''`, execute granted to `authenticated` only, append-only history for decisions. Prove each one on your own isolated stack (`node scripts/db/prepare-stack.mjs --project <name> --ports <port>`), never the default 554xx stack or a hosted project, and stop the stack with `--no-backup` when done. Regenerate `lib/db/types.ts` from your stack and keep only your additions.
4. Every behaviour change gets tests: unit or UI tests for logic and screens, `tests/security/*.test.ts` for every new database function (own venue, other venue, staff vs manager vs admin, inactive, anon).
5. Before finishing: `pnpm typecheck`, `pnpm exec eslint . --ignore-pattern '.claude/**'`, Prettier on changed files, your tests, and `pnpm test`. Report real output.
6. Commit on your branch (Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). Never push, open a PR, deploy, run hosted migrations, change env vars, read `.env*`, or run `lci`.
7. Report: built, files, checks with output, not done, and what other tasks must know (exported names, schema changes).
